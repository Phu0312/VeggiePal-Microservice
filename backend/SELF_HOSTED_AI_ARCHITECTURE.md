# Self-hosted AI architecture

`AiProviderClient` is the text completion contract. `ProviderConfig` binds chat, meal planning, recommendations and moderation independently to `LocalAiClient` by default, with explicit Groq selection available per feature. `LocalAiClient` sends OpenAI-compatible `/v1/chat/completions` requests to a single llama.cpp server. `VideoProcessingWorker` still injects `GroqClient` directly for speech transcription and recipe extraction.

Chat preserves quota reservation, conversation history and persistence. Meal planning still filters recipes and allergens in Java, validates the selected IDs, and derives nutrition values from recipe-service data. Its pre-existing deterministic planner can produce a plan when generation fails. Recommendations rank only candidates fetched from blog-service and recipe-service, filter recipe candidates against the user's allergens with the meal planner's validator, and discard IDs absent from those candidates. A failed allergy lookup returns a controlled downstream error. Blog recommendations contain published content rather than structured ingredient data, so ingredient-level allergy screening applies to recipe candidates only. Moderation saves the existing decision and audit case; inference failure queues `REVIEW_REQUIRED` for an administrator. The moderation endpoint receives text only, including for VIDEO content; Qwen does not inspect frames or pixels.

The model is Qwen2.5-1.5B-Instruct, quantized as GGUF Q4_K_M. The [official GGUF repository](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF) lists the 1.12 GB file and Apache 2.0 license. Four-bit quantization reduces weight memory relative to the FP16 file (3.56 GB), with possible quality loss. llama.cpp reads this GGUF directly and supports partial GPU offload. ONNX conversion adds a second model format and runtime without a benefit for this shared generative path; a future dedicated classifier could use ONNX separately. The [llama.cpp server guide](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) documents `/health`, `/v1/chat/completions`, context, batch, parallel and GPU-layer options. The [Docker guide](https://github.com/ggml-org/llama.cpp/blob/master/docs/docker.md) documents the CUDA server image.

Current limitations: a 1.5B text model can misclassify nuanced Vietnamese content; confidence returned by the model is an uncalibrated score. Moderation sends uncertain or failed classifications to manual review. A 2,048-token context may be insufficient for a large recipe list; the planner may then use its deterministic path. No GPU throughput or quality claim is made without measuring on the target machine.
